# software-engineering-project-comp3415

Contributing

To keep the repository organized and ensure changes are reviewed before being added to the main codebase, all team members should follow the workflow below.

Branches

Do not make changes directly to main.

Create a separate branch for each feature, bug fix, or other piece of work.

Use descriptive branch names following these conventions:

feature/feature-name
fix/bug-name
docs/documentation-change
refactor/component-name

Examples:

feature/syllabus-upload
feature/calendar-integration
fix/login-validation
docs/update-readme
Pull Requests

All changes to main must go through a pull request.

Before merging:

Push your changes to your branch.
Open a pull request into main.
Clearly describe what was changed and why.
At least one other team member must review and approve the pull request.
Resolve any review comments or discussions.
Merge only after the required approval has been received.
General Guidelines
Keep branches focused on one feature, fix, or task whenever possible.
Write clear and descriptive commit messages.
Pull the latest changes before starting new work.
Do not force push to main.
Do not delete or bypass repository protection rules.
Review another team member's code before approving a pull request.
Test your changes before requesting a review.
Avoid committing secrets, API keys, passwords, or environment files containing sensitive information.

The main branch should remain stable and contain only reviewed and approved changes.
